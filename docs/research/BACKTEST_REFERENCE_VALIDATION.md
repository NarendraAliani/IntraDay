# Backtest Reference Validation

Checkpoint 30. Independent reference validation of the backtest engine
(`src/intraday/research/backtesting`), against a deliberately separate,
independently-derived reference implementation
(`tests/validation/reference_engine.py`).

**Verdict: PASS.** Zero unexplained mismatches across signals, trades,
costs, equity/drawdown, portfolio behaviour, and look-ahead/causality
checks, on both fixtures used. All comparisons that ran were
EXACT_MATCH — no tolerance was needed anywhere.

This report does **not** claim the EMA Crossover strategy is
profitable, safe, or production-ready. It claims only that the
**backtest engine computes what it is documented to compute**, verified
against an independent second implementation.

---

## 1. Validation Objective

Answer: does the production backtest engine produce materially correct
results when compared against an independent reference for the same
instrument, historical bars, strategy rules, execution assumptions, and
cost model?

Scope: `run_backtest()` (single-instrument) and `run_portfolio_backtest()`
(multi-instrument), using the `ema_crossover` strategy (fast_lookback=3,
slow_lookback=6) and `verified_nse_cash_equity_intraday_cost_model()`
(Checkpoint 29).

## 2. Dataset Identity

Two frozen synthetic datasets and one auxiliary portfolio dataset, all
defined in `tests/validation/fixtures.py`:

| Dataset ID | Instrument | Bars | Purpose |
|---|---|---|---|
| `MICRO-EMA-CROSSOVER-V1` | `NSE:VALIDATION01` | 30 | Hand-designed micro fixture: flat warm-up, clean uptrend, sharp reversal, flat tail. Exercises `signal_reversal` and `end_of_data` close reasons. |
| `EXTENDED-EMA-CROSSOVER-V1` | `NSE:VALIDATION02` | 150 | Larger, seeded (`random.Random(20260814)`) pseudo-random walk. |
| `MICRO-EMA-CROSSOVER-INSTRUMENT-B-V1` | `NSE:VALIDATION03` | 30 | Second instrument (opposite trend shape) for portfolio validation. |

Each dataset carries: `dataset_id`, `source`, `retrieval_timestamp`,
`instrument_id`, `exchange`, `timeframe`, `start`/`end`, `bar_count`, and
a SHA-256 `checksum` over its own bar data — the same identity fields a
real frozen market dataset would carry.

**Honest limitation, stated explicitly:** this environment has no
verified Dhan credential and no licensed real-market historical data
source. Neither dataset above is real NSE market data. Both are
synthetic, generated by a fixed and documented algorithm, and frozen
with a dataset ID and checksum exactly as real data would be — but the
prices themselves were never traded. `test_fixture_checksum_is_deterministic`
proves the freeze is reproducible; it does not and cannot prove market
realism. This limitation was disclosed rather than papered over, per
this project's established practice (the same disclosure pattern used
for the unavailable NSE primary-source cross-check in Checkpoint 29 and
for browser automation in Checkpoints 28-30).

## 3. Reference Implementation

`tests/validation/reference_engine.py` — deliberately independent of
the production engine:

- Own dataclasses (`ReferenceBar`, `ReferenceSignal`, `ReferenceTrade`,
  `ReferenceEquityPoint`) — does not reuse `domain.market_data.contracts.Bar`
  or any production result type.
- Own EMA computation (`_compute_ema`): a from-scratch iterative
  recurrence (seed = simple average of first `lookback` closes, then
  `alpha = 2/(lookback+1)`), never calling
  `signal_intelligence.feature_engine.ema`.
- Own, independently re-typed cost formulas (`_cost_leg`), re-derived
  from the Checkpoint 29 written specification, never importing
  `cost_model.py`.
- A separate, non-generalized multi-instrument loop
  (`run_reference_portfolio`) for portfolio validation, not a
  refactor of the single-instrument loop.

Mechanically proven separate by `tests/validation/test_reference_engine_isolation.py`
(ast-based import scan, both directions):
`test_no_src_module_imports_the_reference_engine` and
`test_reference_engine_does_not_import_the_production_engine` — both
pass.

## 4. Execution Assumptions (identical in both implementations)

- Signal computed from bar `i`'s close; fill occurs at bar `i+1`'s open.
- End-of-series: open position force-closed at the final bar's own
  close, reason `end_of_data`.
- Zero slippage (isolates execution/cost logic from a slippage model
  that is a separate, already-tested concern).
- Fixed quantity sizing (`QUANTITY = 10`), `initial_capital = 100000`.
- Cost model: `verified_nse_cash_equity_intraday_cost_model()`
  (brokerage → exchange → SEBI → GST[on unrounded sum] → STT[sell-only]
  → stamp duty[buy-only], each rounded once via `ROUND_HALF_UP` to 2dp).
- Mark price convention: a bar's own close (both `MarkToMarketPoint`
  and `ReferenceEquityPoint` use this identically — confirmed before
  any equity comparison, per Part 8's requirement to verify convention
  equivalence before claiming a mismatch).

## 5. Signal Reconciliation

`test_signal_reconciliation_micro_fixture`,
`test_signal_and_trade_reconciliation_extended_fixture`.

Methodology: the real engine's own feature-computation dispatcher and
`strategy.evaluate()` (the same public API `engine.py` itself calls)
were invoked bar-by-bar and compared against
`reference.signals[i].direction`.

Result: **0 mismatches** on 30 bars (micro) and 150 bars (extended).
`warmup_bars == SLOW_LOOKBACK - 1 == 5` in both, and cross-checked
against `result.validation.warmup_bars` from the real engine.

## 6. Trade Reconciliation

`test_trade_reconciliation_micro_fixture`.

Compared field-by-field (`zip(..., strict=True)`, so a trade-count
mismatch itself would fail the test): `direction`, `entry_timestamp`,
`entry_price`, `exit_timestamp`, `exit_price`, `quantity`, `reason`,
`gross_pnl`.

Result: **exact match**, all fields, both trades in the micro fixture
(one `signal_reversal` close, one `end_of_data` close — both
close-reason paths exercised).

## 7. Cost Reconciliation

`test_cost_reconciliation_micro_fixture`.

Compared `trade.cost_breakdown.{brokerage, stt, exchange_transaction_charges,
sebi_charges, gst, stamp_duty}` against the reference's independently
re-typed cost dict, plus aggregate `costs` and `net_pnl`.

Result: **exact match**, all six cost components, both trades.

## 8. Equity / Drawdown Reconciliation

`test_equity_reconciliation_micro_fixture`.

Mark-price convention (bar's own close) confirmed identical in both
implementations before any point-by-point comparison. Then
`result.mark_to_market_curve` compared point-by-point against
`reference.equity_curve`, and `result.metrics.max_drawdown` cross-checked
against `max(p.drawdown for p in reference.equity_curve)`.

Result: **exact match**, every bar's realized/unrealized/total
equity and drawdown; max drawdown 21.10 with duration 5 bars, agreeing
in both.

## 9. Look-Ahead / Causality Validation

`test_truncation_does_not_change_earlier_reference_signals`.

The production engine's own causality (bar `i` close → signal → bar
`i+1` open fill) was already established in earlier checkpoints. This
checkpoint additionally re-confirms the same property holds in the
**reference** implementation, independently: the fixture was truncated
at cutoffs 10, 15, 20, 25 and all signals computed at indices before
each cutoff were asserted identical regardless of what data appeared
after the cutoff.

Result: **no look-ahead in the reference implementation either** —
both code paths derive a bar's signal from only that bar and earlier
ones.

## 10. Portfolio Validation

`test_portfolio_reconciliation_two_instruments` — 2 instruments
(`MICRO-EMA-CROSSOVER-V1` + `MICRO-EMA-CROSSOVER-INSTRUMENT-B-V1`),
shared capital pool, `max_concurrent_positions = 2`, run through both
`run_portfolio_backtest()` (production) and `run_reference_portfolio()`
(a separate, independently-written multi-instrument reference loop, not
a generalization of the single-instrument reference).

Compared: trade count, `rejected_entries` count, aggregate net P&L
across both instruments.

Result: **exact match** on all three.

## 13. Manual Trade Audit

Three trades, hand-computed independently of both implementations
(`tests/validation/test_manual_trade_audit.py`), chosen to cover a long
win, a short win closed by `end_of_data`, and a short loss (not
cherry-picked to only profitable outcomes):

1. **`ema_crossover-1`** (`MICRO-EMA-CROSSOVER-V1`), BULLISH,
   entry 101 → exit 108, qty 10, `signal_reversal`.
   Gross = (108−101)×10 = **70**. Entry (BUY, notional 1010): brokerage
   0.30, exchange 0.03, sebi 0.00, gst 0.06, stamp 0.03 → 0.42. Exit
   (SELL, notional 1080): brokerage 0.32, exchange 0.03, sebi 0.00, gst
   0.06, stt 0.27 → 0.68. Total costs **1.10**. Net = 70 − 1.10 =
   **68.90**. Matches engine output exactly.

2. **`ema_crossover-2`** (`MICRO-EMA-CROSSOVER-V1`), BEARISH,
   entry 106 → exit 102, qty 10, `end_of_data`.
   Gross = (106−102)×10 = **40**. Entry (SELL, notional 1060): brokerage
   0.32, exchange 0.03, sebi 0.00, gst 0.06, stt 0.27 → 0.68. Exit (BUY,
   notional 1020): brokerage 0.31, exchange 0.03, sebi 0.00, gst 0.06,
   stamp 0.03 → 0.43. Total costs **1.11**. Net = 40 − 1.11 = **38.89**.
   Matches engine output exactly.

3. **`ema_crossover-2`** (`EXTENDED-EMA-CROSSOVER-V1`), BEARISH,
   entry 234 → exit 235, qty 10, `signal_reversal` (a loss).
   Gross = (234−235)×10 = **−10**. Entry (SELL, notional 2340): brokerage
   0.70, exchange 0.07, sebi 0.00, gst 0.14, stt 0.59 → 1.50. Exit (BUY,
   notional 2350): brokerage 0.71, exchange 0.07, sebi 0.00, gst 0.14,
   stamp 0.07 → 0.99. Total costs **2.49**. Net = −10 − 2.49 = **−12.49**.
   Matches engine output exactly.

All three are pinned as permanent regression assertions in
`test_manual_trade_audit.py` — any future change to the engine or cost
model that alters these figures will fail CI.
